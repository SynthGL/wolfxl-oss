## Reproduction and interpretation

- Run label: 2026-10-27; the unmodified UTC timestamp is on 2026-10-28.
- CPU from `lscpu`: AMD EPYC 9655 96-Core Processor, 16 virtual CPUs.
  The deep harness's `cpu_brand` is null on Linux; the same-node CPU capture
  and full package identities are in `metadata.provenance`.
- Python 3.13.15; published PyPI WolfXL 2.0.21 and openpyxl 3.1.5.
  The installed native library matches the PyPI wheel, verified by SHA-256.
  Harness source: `405465b04e67f844ef1013e755e1f25f7d2d59bc`.
- Five measured rounds at 10,000 x 5 cells and 200,000 x 8 cells. The small
  case discards one warmup; the large case has no discarded warmup, matching
  the existing harness. The OS page cache was not flushed. This is not a
  cold-start measurement.
- Overall timeout: 600 seconds. The deep harness has no per-round timeout.
  It checks both changed cells by reopening each saved workbook with openpyxl.
- Operation claims use `phase_medians_seconds.modify_save` and
  `operation_comparisons`, not `median_seconds` or `comparisons`. The latter
  include fixture copying and openpyxl verification, which mask the operation
  difference. Both timing bases remain in the raw file.
- No peak-RSS pass was run here. See the ecosystem results for fresh-process
  large-read and large-write RSS. No version-to-version modify claim is made.

```bash
.bench/bin/python benchmarks/benchmark_openpyxl_vs_wolfxl.py --rounds 5 --large-rounds 5 --case modify_two_cells_plain --case large_modify_two_cells_plain --no-memory --output-dir benchmarks/results --prefix 2026-10-27-community-2.0.21-modify-linux-epyc
```

The command uses repository-relative output paths. The measured tree was clean
and the library came from the installed wheel, not the checkout.

`metadata.provenance` was added after timing, using identities captured on
the measured machine. All other JSON fields are unmodified harness output.
